# NBA Analyzer — 2026 Playoffs archive + 2026-27 Regular Season model

`index.html` is a landing page with two entries:

- **`season.html` — 2026-27 Regular Season** (live). A deliberately small game model (net rating × pace + home court + rest ± roster vs rating, players valued by Box Plus/Minus ± aging ± roster fit; P = Φ(margin/12.5)) blended with the NB.AI Monte Carlo model and compared against the market line, plus player prop projections and an out-of-sample ledger that scores every source. Code in `js/season/`, tests in `test-season.js`. See [Regular season model](#regular-season-model-2026-27) below.
- **`playoffs.html` — 2026 Playoffs** (archive, complete — Knicks 4-1). Everything described in the rest of this file.

## Regular season model (2026-27)

Daily routine (Node 18+, no dependencies) — one script picks the phase by time of day and runs each phase at most once per day:

```bash
./season-daily.sh
```

Any hour it settles open ledger rows from ESPN; from 11:00 ET it also snapshots the NB.AI feed and records tonight's predictions (`--record` refuses a feed that isn't today's slate, so an early run can't record stale lineups). `--status` shows what has run today, `--force` reruns. If NB.AI still hasn't refreshed by 17:00 ET (it is updated by hand), or can't be reached, the run records from an ESPN fallback slate instead (`node fetch-slate.js --espn`, or `./season-daily.sh --espn` to use it at any hour): team priors from `js/season/data/team-priors.js`, this season's results and player lines from ESPN box scores, availability from ESPN's injury report and current rosters, DraftKings lines from ESPN. Those rows have no NB.AI probability, show an "ESPN" tag on the Ledger tab, and are replaced if NB.AI refreshes before tip-off; the run prints `check:` lines for regulars it had to guess about — one who sat out his team's last two games but isn't on the report (counted in), or one on the roster with no game for the team yet and no designation (left out) — so you can check them before committing. A Day-To-Day note counts only if it is about tonight's game. The underlying commands are `node fetch-slate.js --settle` / `--record` if you want them by hand. Best cadence: once in the morning (settle) and once after ~1 PM ET (record). The same commands are pinned at the top of `DAILY_UPDATE.md`. Run `node test-season.js` before committing, and commit `js/season/data/slate-snapshot.js` and `js/season/data/season-ledger.js` after each run. The NB.AI site (`https://nb-ai.josh2899.chatgpt.site/`) sends no CORS headers, so the page reads the committed snapshot; the Data tab also accepts a pasted `saved.json` as a browser-local fallback.

How the pieces fit:

| File | Role |
|---|---|
| `js/season/data/season-constants.js` | Every prior (HCA 2.5, σ 12.5, shrink K=20, last-season retention 0.75, rest, BPM value constants, player-baseline blending, prop sd) with its source, plus `SEASON_ENGINE_VERSION` |
| `js/season/data/chemistry-fit.js` | Generated by `node research-team-fit.js --write`: roster-fit coefficients (continuity, rebounding overlap) and the fit's provenance |
| `js/season/data/aging-fit.js` | Generated by `node research-team-fit.js --write`: expected BPM change from a player's prior by age this season, plus the replay result it was chosen on |
| `js/season/data/player-priors.js` | Generated by `node fetch-priors.js`: 2024-25 and 2025-26 per-game lines (ESPN, official), BPM and role rates (Basketball-Reference), 2025-26 games by team, each player's 2026-27 age, and the box → BPM fit. Keyed by ESPN id, same as the feed |
| `js/season/data/team-priors.js` | Last season's offense/defense per 100 possessions and pace for all 30 teams, fixed from NB.AI's Nov 2 feed; the ESPN fallback and the backtest read it (NB.AI's daily feeds revise these and carry only that day's teams) |
| `js/season/data/team-ratings.js` | Generated by `node replay-season.js --ratings`: Basketball-Reference 2025-26 final team ratings, for the replay |
| `js/season/data/season-replay.js` | Generated by `node replay-season.js`: walk-forward predictions with provenance, scored apart from the ledger |
| `js/season/data/user-bets.js` | Bets you placed: each leg's game, side, DraftKings close and the model's and market's probability, graded against the ledger result |
| `js/season/adapters.js` | NB.AI feed → normalized `SeasonSlate`; ESPN scoreboard → results; ESPN box scores, pickcenter, injuries and rosters → the same `SeasonSlate` (the fallback slate and the backtest's replays) |
| `js/season/engine.js` | `projectSeasonGame` — margin waterfall, win prob, total, team strength blend; `playerProfile` (prior seasons blended with this one), `calcRosterAdjustment` (tonight's roster vs the roster the rating was earned with, plus aging of last season's rating), `calcRosterFit` (continuity and rebounding overlap) |
| `js/season/props.js` | Per-minute rates × projected minutes × usage redistribution × opponent D × pace; `probOver` |
| `js/season/ensemble.js` | Log-odds pooling, no-vig market, Brier/log-loss scoring, logistic stacking |
| `js/season/ledger.js` | Committed + browser-local prediction rows; ESPN-fallback rows are replaceable until tip-off |
| `js/season/ui.js` | Tonight / Results by Day (one day at a time: arrows, ← →, or a calendar) / Matchup Lab / Ledger & Scoring / Data tabs; each linkable, e.g. `season.html#results/2026-11-04` |
| `fetch-priors.js` | Rebuilds `player-priors.js`; re-measures replacement-level BPM, the BPM → points calibration and the box → BPM fit on every run. Run once per season (or if Basketball-Reference revises) |
| `research-team-fit.js` | Measures what summed player value misses on every team-season since 2015-16 (Basketball-Reference, cached in `.cache/bref/`): the age curve, the roster-fit (chemistry) features, and a replay of the engine's opening-night projection used to choose aging and retention out of sample. `--write` regenerates `aging-fit.js` and `chemistry-fit.js`. Run once per season |
| `research-season-update.js` | Walks every regular-season game of 2015-16 … 2025-26 forward (Basketball-Reference schedules, cached) from point-in-time opening priors and chooses update speed K, home court, back-to-back cost and σ leave-one-season-out |
| `research-season-rest.js` | Back-to-back cost with absences removed: ESPN box scores for 2023-24 … 2025-26 (cached in `.cache/espn-nba/hist/`) mark which regulars sat; the residual of the point-in-time predictions is regressed on rest and missing minutes |
| `research-season-prior.js` | Scores the opening-night projection point-in-time (each player's first team of the season, minutes and BPM from the two seasons before) on 330 team-seasons against the preseason win-total market, by roster stability; tests what explains the gap (two seasons of team rating, last season's luck, age, coaching change, continuity-dependent carryover) and the rotation-minutes cap the engine uses |
| `backtest-season.js` | Replays every completed 2026-27 game through the engine (ratings from games before the date, real lineups) and scores it against results and DraftKings' opening/closing lines: winners, Brier, margin, and game totals (error, bias, and over/under against the closing total). `--compare <git ref>` A/Bs an older engine; `--lineups last-game` removes the hindsight advantage; the `no fit` and `no aging` variants show those steps' contributions. Run it after any engine change |

Combination rule: equal-weight log-odds average of the two models (convex scoring rules guarantee it can't do worse than the average member). The market is displayed, not blended, until the ledger has ~150 settled games with all three forecasts — at that point `stackWeightsFromLedger` fits logit P on [ours, NB.AI, market] and tells you whether either model carries information the closing line doesn't. Benchmarks to beat: no-vig closing line ≈ 67.8% winners / Brier 0.205 / margin MAE ≈ 10.

Player value: each player's Box Plus/Minus (two prior seasons weighted 1.0/0.5, regressed toward replacement, blended with a box-score estimate from this season's games) converts to points per game as (BPM + 2) × min/48 × pace/100 × 0.885 — the 0.885 is the measured slope of team point differential on minutes-weighted BPM (R² 0.998). The roster step moves the margin by each player's value × (availability tonight − his share of the team's rating), and removes departed players' share, so an injury that predates the rating or an off-season trade is neither double-counted nor missed. Backtest on Oct 20 – Nov 1 2026 (92 games, leak-free lineups): Brier 0.180 vs 0.198 for the previous Game Score engine and 0.192 for DraftKings' closing line — consistent direction, not yet beyond noise; props at actual minutes improved from 5.22 to 4.37 points MAE.

Roster fit ("chemistry"): `research-team-fit.js` predicts every team-season from 2015-16 to 2025-26 (330) from its players' prior-season BPM at their actual minutes, and asks whether the miss on the team's adjusted net rating depends on how the roster fits. Seven features were fixed before looking. Two held up in leave-one-season-out cross-validation; the rest did not:

| Feature | Per 100 possessions (shrunk) | Verdict |
|---|---|---|
| Offseason continuity (share of minutes from last season's roster) | +2.5 per 100% | kept: positive in 9 of 11 seasons; leans toward a turnover penalty more than a continuity bonus |
| Rebounding overlap (on-floor rebound-rate sum) | −0.11 per point | kept: same sign in both halves of the sample; matches the diminishing-returns literature |
| Usage overlap, playmaking overlap, spacing, shooter count, stacked non-shooting bigs | — | not detectable beyond what BPM already prices |

Mid-season arrivals were excluded on purpose: teams that take on players at the deadline are usually sellers, so that signal is tanking, not chemistry. The step is capped at ±2 points per team and fades as this season's results (which already contain the fit) take over the rating; on opening-week rosters it ranges about ±0.9. Cross-validated error fell from 2.884 to 2.848 points per 100. The 92-game backtest cannot resolve an effect this size (Brier +0.002 ± 0.0013 versus no fit).

Aging: players' BPM moves predictably with age. Measured on 3,318 player-seasons against the engine's own prior, the expected change is about +0.8 at ages 20–22, near zero at 26, −0.4 at 30 and −0.8 at 35 (`aging-fit.js`). The engine applies it to last season's part of the team rating: each returning player's share of last season's games × his availability tonight × the value change, fading as this season's results take over. Arrivals keep their prior value. Replaying the engine's opening-night projection on 330 team-seasons chose this form out of sample:

| Variant (replay, per 100 possessions) | RMSE |
|---|---|
| Engine before (retention 0.80, no aging) | 3.066 |
| Retention 0.70, no aging | 3.035 (out of sample) |
| Aging on every player | 3.056 out of sample, worse than retention alone |
| Aging of last season's rating, retention 0.75 (adopted) | 3.010 (3.019 out of sample) |

Aging arrivals made projections worse. The curve is measured on players who kept their minutes, which flatters young players, and that bias matters most when pricing a young player on a new team. On the 92 games of 2026-27 the aging step improved Brier by 0.0024–0.0027 ± 0.0014 versus the same engine without it (both lineup modes; about 1.8 SE, consistent with the replay but not conclusive on its own). The same replay confirms the roster-fit step still helps under the adopted settings (3.034 without it). On tonight's rosters it ranges from −0.8 (Knicks, core aged 30–31) to +0.4 (Grizzlies, 76ers and Raptors).
 players with no NBA minutes in the last two seasons or this one (rookies, two-ways) are listed as "not valued"; team priors are last season's points for/against per possession; the feed only carries the teams playing that day, so the Matchup Lab is limited to those teams; BPM is box-score-based, so defensive specialists remain undervalued relative to on/off metrics. After an engine change, bump `SEASON_ENGINE_VERSION` (season.html's `?v=` must match — `test-season.js` checks).

### Walk-forward replay (`replay-season.js`)

Predicts every past game from opening night on using only what was published before it tipped, with the engine frozen at one version, and keeps the result apart from the live ledger (Results by Day → *Replay from opening night*). Inputs, each cut to the morning of the day:

| Input | Source | Point-in-time rule |
|---|---|---|
| Team ratings | `team-ratings.js`: Basketball-Reference 2025-26 final ORtg/DRtg/pace | fixed; NB.AI's "prior" is not used because it absorbs this season's games |
| This season | ESPN finals and box scores | games dated before the day |
| Rosters | last 2025-26 team → archived opening rosters (ESPN, NBA.com for MIL) captured before opening day → dated BR signings/waivers → box scores → the day's report | events before the day, ordered by ET time (a roster captured in the morning precedes that day's dated moves); a preseason box cannot undo a waiver; a did-not-play listing after a waiver does not re-add a player |
| Availability | official NBA injury report (`parse-injury-report.py`) | the report for the latest half-hour slot at least 60 min before that game's tip (each PDF is posted within seconds of its slot); a report moves a player only for games whose cutoff is after it; Out 0 / Doubtful 0.1 / Questionable 0.5 / Probable 0.9; a player who did not dress last game and is on neither report counts as not with the team |
| Preseason (variant) | NBA-vs-NBA preseason margin per game × 0.099 | coefficient from 2016–2026 (0.0993 on a projected-minutes base) |

Guards: only listed data files load (the snapshot, ledger and NB.AI-derived priors are refused), a URL allow-list admits only historical sources, `--check` replays sample days with everything on or after the day deleted, with every later result, box score and report scrambled, and each game again cut at its own report cutoff (predictions must be byte-identical, and a control must change), unmatched report names that could change an availability stop the run, and `--score` refuses to run until the spec files are committed. `--qa` and `--inspect DATE TEAM` compare rosters with who dressed (input checking only). Spec `replay-2` followed an independent review of `replay-1` (snapshot time ordering, a later game's report reaching an earlier game, leak-check coverage); it changed 3 of 121 predictions. Disclosed: the engine version was adopted partly on ~92 of these games (aging, commit f3e9ff4), so the replay is not fully independent of the engine's design. Spec `replay-3` moves to engine `2026-11-05.minutes-v1` (minutes capped at 240, chosen on past seasons) and adds the engine and its constants to the frozen files. Scored once: engine 68.6% winners / Brier 0.1981 (replay-2 0.1973, paired +0.0008 ± 0.0029); DK close 0.1927; games 10+ points from the close fell from 14 (our side won 4, market expected 6.9) to 12 (won 6, expected 5.5). Spec `replay-4` lowers home court to 2.0 (engine `2026-11-05.minutes-hca2`, chosen on 13,209 past games by `research-season-update.js`, which also confirmed K = 20 and σ = 12.5): Brier 0.1961 (replay-3 −0.0020 ± 0.0012), DK close 0.1927 (gap +0.0034 ± 0.0048), mean home margin 2.46 against the close's 2.41 (actual 1.61). Disclosed: the replay's home lean (+1.6) was known before the change, though the value came from past seasons. Spec `replay-5` sets the back-to-back cost to 2.0 (engine `2026-11-05.b2b2`; `research-season-rest.js` measures 2.12 ± 0.44 on 3,690 recent games once missing regulars are removed): Brier 0.1958 (replay-4 −0.0004 ± 0.0009, 22 games changed), gap to the close +0.0030 ± 0.0048. A draft-slot rookie value was tested in `research-season-prior.js` and not adopted (only top-3 picks beat replacement; team projections did not improve). Known limits: rookies are valued at replacement; a handful of two-way/camp players on opening rosters count as available without dressing. The PDF reader needs `python3 -m venv .cache/pyenv && .cache/pyenv/bin/pip install pypdf` once.

# 2026 NBA Playoff Analyzer — Advanced Metrics Edition (archive)

A comprehensive, research-backed NBA playoff prediction and analysis tool built with vanilla HTML, CSS, and JavaScript. Tracks 2026 NBA Playoff series game-by-game with projections, real-time result tracking, Monte Carlo simulation, an interactive scenario builder, and a Compound Historical Scenarios engine that fires evidence-backed adjustments when stacked conditions match.

**Current model accuracy:** R1 final 28/48 ML (58.3%, 9.6pt avg margin error). Series-stage curve: G1–G3 50% → G4–G7 67% — accuracy improves as in-series data accumulates. R2 completed (4 series: NYK 4-0 PHI, SAS 4-2 MIN, OKC 4-0 LAL, CLE 4-3 DET). Conference Finals in progress (WCF G3 OKC leads 2-1 after wrong-winner CF G1/G3 R3-out-of-sample misses; ECF G3 NYK leads 2-0 going into 5/23).

## Features

- **Home Landing Page** (Phase 57) — adaptive layout. Tonight's games render as auto-fit cards with the live blended ML pick, projected score, slate context, and an "Open series →" link. Featured Parlays section has a toggle between **Reliable Floor** (80%+ floor-style hit rate) and **Traditional** (regression / bounce-back / chaos). Latest News feed (curated injury/availability notes). Tonight's Bets render as per-series columns when ≥2 games are scheduled; News + Bets sit side-by-side when only one game is on (Conference Finals / Finals).
- **Unified Ensemble Prediction System** (Phase 41) — blends manual analysis, a multi-factor engine, and a 10,000-iteration Monte Carlo chaos simulation into a single probability output with calibrated standard deviation (SD ±11.6)
- **Compound Historical Scenario Engine** (Phase 52) — conditional-narrowing system. Each player carries stacked historical conditions (role + opponent team + venue + coach + primary defender + playoff context + health). When all conditions match, the scenario fires and adjusts projections; multiple matches compound at 70% decay. Cascade model propagates teammate adjustments when a star delta exceeds 2pts. Rendered inline on every game tab and bet card.
- **18-step Game Projection Engine** incorporating home court, fatigue, chemistry, matchup suppression, star elevation, coaching adjustments, 3PT variance, role flexibility, youth breakouts, turnover tendencies, compound historical scenarios, and more
- **Multiplicative Context Architecture** (Phase 51) — Fatigue, Scheme Persistence, and Inconsistency are proportional to the base talent edge (±12% / ±20% / 15% compression) instead of fixed-point additions. WIN_PROB_SCALE recalibrated 15→35 for realistic 55-82% favorite range, supported by 2025+2026 cross-year validation showing underdogs win 41.7% of playoff games.
- **Dynamic Per-Player Rating Adjustments** (Phase 50) — injury severity, playoff ascension, and coaching scheme adjustments wired into `calcTeamRating` per player rather than as team-level flat bonuses.
- **Monte Carlo Chaos Simulation** (Phase 40, 10K iterations Phase 45) — models correlated scoring runs, momentum swings, fatigue cascades, foul trouble, capitulation threshold, and cascading collapse using interdependent random variables.
- **Projection Lineage Waterfall** (Phase 42) — SVG visualization showing each engine factor's delta contribution to the final predicted margin, with a running margin tracker
- **Post-Game Factor Attribution** (Phase 42) — after a game completes, distributes prediction error proportionally across lineage steps to identify which factors over/under-predicted
- **SPM Chemistry Engine** based on Maymin et al. (2013) — models player synergy across 8 skill dimensions
- **Scenario Builder** — toggle players in/out to see how injuries and lineup changes shift win probability in real time
- **Series Graduation** (Phase 42) — handles round transitions with fatigue/injury carryover when a series concludes. Used to graduate all 4 R2 series from R1 winners.
- **Round-Level Navigation** — R1/R2/Conference Finals/Finals hierarchy with persistent state
- **Declarative Bet Card Schema** (Phase 55) — bet cards migrated from hand-styled HTML to a typed `BETS` array + `BET_SLATES` metadata + single `renderBetCard()` renderer. Type/pick/odds/facts/chs/confidence/thesis[]/narrative/result fields. 36 R2 cards through one pipeline; bets.js dropped 3578→3252 lines. Adding a new G3 slate is ~10 lines of data.
- **Dynamic Blended Bets** (Phase 48) — every R2 ML/spread/margin pick interpolated from `calcBlendedProjection()` at render time via `dml`/`dmargin`/`dwinner` helpers. Bet cards always reflect current model state.
- **2025 Playoffs Validation Dataset** — `playoffs_2025_validation.js` tracks game-by-game 2025 results as an independent validation set; `test-projections.js` TEST 6 covers the CHS engine with 19 new assertions (3447→3466 total, 0 failures)
- **Model Learnings** page documenting 56 phases of model evolution with what worked, what failed, and calibration updates
- **localStorage V3** — series-ID keyed persistence with backward-compatible V2 migration

## How It Works

The prediction model combines multiple research-backed components:

- **Player Composite Rating** — Weighted blend of PER, TS%, EPM, BPM, Usage context, WS/48, On/Off, and Clutch metrics (scale 0-100)
- **Team Rating** — Aggregated from player ratings using a replacement-level slot system, integrated with VORP/USG (Yla-Autio 2022) and LEBRON/WAR (BBall Index)
- **Blended Win Probability** — Combines manual picks, engine projections, and Monte Carlo simulation into a unified ensemble probability per game
- **Margin Projection** — Converts win probability to expected margin using talent gap amplifiers, depth disparity, star absence adjustments, and chaos simulation variance
- **Fatigue Monitor** — Tracks rest days, minutes load, injury risk, and active injury status per player per game
- **Defensive Matchup Suppression** — Models how elite defenders reduce opponent star output using D-LEBRON ratings, with scheme-driven vs. variance-driven categorization
- **Star Elevation Effect** — Models how elite players elevate scoring in high-stakes games (elimination, close-out)
- **Coaching Adjustment Model** — Post-loss adaptation patterns calibrated per head coach with historical adjustment data

## Getting Started

No build tools or dependencies required. Open `playoffs.html` (or the `index.html` landing page) in any modern browser:

```bash
# Clone the repo
git clone https://github.com/gasperjw1/nba-playoff-analyzer.git
cd nba-playoff-analyzer

# Open in browser
open playoffs.html
# or
python3 -m http.server 8000   # then visit http://localhost:8000
```

## Usage

1. **Series Analysis** — Select a conference round and series from the tabs. View rosters, advanced stats, synergy lineups, coaching analysis, projection lineage waterfall, and the per-game CHS panel showing which compound scenarios fired and how they cascaded across teammates.
2. **Scenario Builder** — Toggle players in/out to simulate injuries or lineup changes. Win probability updates instantly.
3. **Game Results** — Click any game card to enter the actual result. The model saves your entries to localStorage V3 and recalculates downstream projections, including post-game attribution.
4. **External Factors** — Add off-court factors (injuries, chemistry issues, motivation) with impact ratings. These feed into the projection engine.
5. **Model Learnings** — Review 56 phases of model evolution, from initial calibration through Monte Carlo integration, ensemble unification, multiplicative context architecture, and the Compound Historical Scenarios engine.
6. **Definitions** — Browse all metric definitions including Projection Lineage, Post-Game Attribution, Series Graduation, Compound Historical Scenarios, Multiplicative Context Factors, Dynamic Rating Adjustments, and the Declarative Bet Card Schema.
7. **Bets** — Per-game ML picks, spreads, player props, and featured parlays. All bets render through one declarative pipeline; ML/margin/winner values interpolate live from the blended model.

Player statistics sourced from Basketball Reference, NBA.com, BBall Index, Fadeaway World, and Sports Illustrated. The model integrates findings from:

- Yla-Autio (2022) — VORP/USG integration for cumulative value and usage efficiency
- Yeung (2020) — Non-linear interaction bonuses (3PT% x DRtg synergy, Pace x Depth)
- Jones & Magel (2016) — Stat differential model (FG%, 3PT%, ORB%, TOV differentials)
- Mateus et al. (2024) — Series-stage pressure amplification and pedigree effects
- Maymin et al. (2013) — Skills Plus Minus chemistry coefficients across 8 dimensions

## Tech Stack

- **HTML/CSS/JS** — No frameworks, no build step, no dependencies
- **localStorage V3** — Series-ID keyed persistence with backward-compatible migration
- **Global scope** — All functions available globally via ordered `<script>` tags (no ES modules)
- **Mobile-responsive** — CSS breakpoints for phone and tablet layouts
